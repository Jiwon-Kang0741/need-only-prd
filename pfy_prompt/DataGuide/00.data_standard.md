# DATA_STANDARD.md
> **적용 범위**: Data Agent 전용. 화면별 `SPEC.md`에는 본 문서의 규칙을 복제하지 않는다.  
> **충돌 해결**: `SPEC.md`와 불일치 시 **항상 본 문서(DATA_STANDARD.md)를 우선**한다.  
> **`cmn_*` 공통 시드 SQL**과 관련해 본 문서와 `SEED_STANDARD.md`가 충돌하는 경우의 해결 순서는 §1.1을 따른다.  
> *※ UI/i18n/Generator/Seed 규칙은 포함하지 않으며, 본 문서로 인해 추가된 Audit/Soft Delete 필드는 차후 `vue_types` 생성 시에도 동일하게 반영한다.*

3. `SPEC.md`
4. AI 임의 추론

### 1.2 검색 API 페이징 필드 (`SearchBaseDto` 정합)

- 화면 `SPEC.md` **§8.1 Search API — Request Fields**에 페이징을 적을 때 필드명은 반드시 **`page`**, **`size`** (`integer`)이다. **`page_index`**, **`page_size`** 등 `SearchBaseDto`와 다른 이름은 SPEC·예시에 사용하지 않는다.
- 검색용 Request DTO는 `SearchBaseDto`를 상속하며, **`page` / `size`는 자식 DTO에 재선언하지 않는다** (코드젠·리뷰 시 동일 규칙).
- 상세 예시·코드 스니펫: **`pfy_prompt/BackendGuide/표준.md`** §4.2 Request DTO, **SearchBaseDto (검색/페이징)** 블록.

### 1.3 AI 추론 금지 및 예외 규칙
Data Agent는 아래 항목을 임의 추론하는 것을 금지한다.
- `varchar` 길이, `numeric(p,s)`의 정밀도
- `nullable` 여부, `unique` 제약, `index` 구성
- `default` 값, `cascade` 정책

**[예외 및 처리 기준]**
- **명시되지 않은 경우**: 원칙적으로 `validation error`를 반환하고 SQL 생성을 중단한다.
- **기본값 예외**: 본 문서 5조(Audit) 및 6조(Soft Delete)에서 강제한 공통 필드의 기본값(`now()`, `'SYSTEM'`, `'N'`)은 SPEC에 없어도 예외적으로 자동 적용한다.
- **금액/수량 예외**: SPEC에 구체적인 p, s 값이 없더라도 '금액' 유형은 `numeric(18,2)`, '수량' 유형은 `numeric(18,4)`를 강제 적용하며 중단하지 않는다.

## 2. Naming Convention
### 2.1 Table
- `snake_case` 사용
- 업무 테이블 prefix: `cptb_` (예: `cptb_risk_mgmt`)

### 2.2 Column
- **PK**: `{table_singular}_id`
- **FK**: `{referenced_table_singular}_id`
- **Boolean**: `is_` 또는 `has_` 접두어 사용
- **코드**: `*_cd` 접미사 사용 (SPEC에 '여부/Flag'로만 기술된 항목은 명시적 boolean 지정이 없다면 `yn_flag`를 우선 적용)
- **코드 표시명 `*_nm`**: **업무 테이블에 물리 컬럼으로 두지 않는다.** 조회 SQL에서만 `*_cd`에 매핑해 채운다. (§2.4)
- **`*_cd` ↔ Mockup 공통코드**: 검색 폼 등에서 **`SearchFormField`의 `name`** 이 업무 `*_cd` 필드와 같고 Mockup에 **정적 Select options**가 있으면, SPEC `# 10.3`에 **class_cd·class_nm·code_cd·code_nm** 행으로 옮기고 시드는 **`SEED_STANDARD.md` §16.4**를 따른다. (표시문은 DB `cmn_code.code_desc` 등 DDL에 맞게 매핑.)

### 2.3 Constraint & Identifier Limit
- **PK**: `pk_{table}`
- **FK**: `fk_{table}_{ref_table}`
- **CHK**: `chk_{table}_{column}`
- **식별자 길이 제한**: PostgreSQL 규격에 따라 테이블, 인덱스, 제약조건 이름은 **최대 63바이트**로 제한한다.
  - *만약 명명 규칙 적용 중 63바이트를 초과할 우려가 있다면, AI는 prefix(`cptb_`)를 제거하거나 뒤쪽 단어부터 의미 있게 축약하여 63바이트 이내로 강제 조정해야 한다.*

### 2.4 코드 표시명 `*_nm` (조회 시에만 채움)

- **업무 테이블(`cptb_*`) DDL**: `*_nm` **물리 컬럼을 생성하지 않는다.** `db_init_sql`의 `CREATE TABLE`에 포함하지 않는다.
- **SELECT(목록·상세)**: `*_cd`(또는 FK)와 **§11·공통코드/마스터**를 조인하거나 스칼라 매핑으로 **결과 집합에만** `*_nm` 별칭을 붙인다. `COALESCE(저장된_nm, 조인명)` 패턴이 아니라, **원칙적으로 저장분 없이 조인·코드표만**으로 채운다.
- **ResDto / Mapper INSERT·UPDATE**: `*_nm` 은 **바인딩하지 않는다.** (응답 전용 필드로만 두거나, MyBatis `resultMap`에서 조회 컬럼에 매핑.)
- **Vue**: API 응답 필드로 표시; **초기 시드 행에 `*_nm` 컬럼을 넣는 업무 테이블 설계는 하지 않는다.**
- 레거시 테이블에 `*_nm` 이 이미 있으면 SPEC에 **`[NEEDS CLARIFICATION]`**·마이그레이션·이관 근거를 명시하고, 신규 화면 코드젠은 가능하면 **조인 전용**으로 맞춘다.

## 3. Data Type Standard

| 논리 분류 | PostgreSQL 타입 | 제약 / 비고 |
| :--- | :--- | :--- |
| **uuid** | `uuid` | PK 사용 시 기본값 `gen_random_uuid()` 가능 |
| **string** | `varchar(n)` | n은 SPEC 명시 값 사용 (누락 시 §1.3에 따라 중단) |
| **text** | `text` | 긴 텍스트 전용 |
| **integer** | `integer` 또는 `bigint` | — |
| **decimal** | `numeric(p,s)` | — |
| **boolean** | `boolean` | `true`/`false` 제약 |
| **yn_flag** | `char(1)` | `'Y'`, `'N'`만 허용하는 `CHECK` 제약조건 강제 (**`del_yn`** 등 Soft Delete는 항상 본 타입, `boolean` 금지) |
| **date** | `date` | 날짜만 저장 |
| **timestamptz** | `timestamptz` | 일시 저장 표준 |

### 3.1 시간 타입 규칙
- 모든 시간/일시 컬럼은 반드시 `timestamptz`를 사용한다. (`timestamp` 사용 금지)

### 3.2 금액/수량 표준
- **금액**: `numeric(18,2)` 강제 적용
- **수량**: `numeric(18,4)` 강제 적용

### 3.3 SPEC `logical_type: uuid` 와 Java·MyBatis (코드젠)

- SPEC §4에서 `logical_type`이 **`uuid`**인 PK·식별자 컬럼은 DB에는 PostgreSQL **`uuid`** 타입(또는 팀 표준 DDL)으로 둘 수 있다.
- **Java DTO·Service·DAO·Mapper XML에서 해당 컬럼은 항상 `java.lang.String`** 으로 모델링한다 (`varchar`/`uuid` DB 컬럼과 매핑).
- **`java.util.UUID`**, **`import java.util.UUID`**, **`javaType="java.util.UUID"`**, **`UUID.randomUUID()`**, **`CommonUtils.getUuid()`** 는 사용하지 않는다 — MyBatis에 UUID 전용 TypeHandler가 없고, 코드젠 `static_check`·sanitize가 위반으로 처리한다.
- SPEC 본문에는 반복 서술 대신 **`spec.template.md` 상단 공통 주의 (PK·ID / Java·MyBatis)** 를 따른다.

### 3.4 `del_yn`(Soft Delete) — `boolean` 금지

- 컬럼명 **`del_yn`** (논리 삭제)은 **항상 논리 타입 `yn_flag` → DB `CHAR(1)` `'Y'/'N'`** 이다. SPEC·DDL에서 **`logical_type: boolean`** 또는 **`BOOLEAN`** 컬럼으로 표기·생성하지 않는다. (상세 §6.1)

### 3.5 업무 일시·등록일 (`reg_dt`, 시점 의미 `*_dt`)

- **등록일·발생일·처리일** 등 시점을 나타내는 컬럼은 SPEC `logical_type`에 **`timestamptz`** 를 사용한다 (날짜만 저장이면 **`date`**). **`string` + 임의 길이(예: 255)** 로 “화면 표시용 문자열만 DB에 적재”하는 정의는 **신규·코드젠 기본에서 사용하지 않는다.**
- DB DDL·`db_init_sql`은 위 시점형 타입으로 생성하고, **Vue 그리드 표시 문자열**은 `FrontendGuide`(DataTable·성능·자주 발생하는 에러)에 따라 **`watch`/`nextTick` 또는 행 데이터 전처리**에서만 만든다. (템플릿 슬롯에서 날짜 포맷 금지.)
- 레거시 `varchar` 저장이 불가피하면 SPEC에 **`[NEEDS CLARIFICATION]`** 및 데이터 출처를 명시한다. 그 외에는 **§3.5를 우선**한다.

## 4. PK/FK 정책
### 4.1 PK 전략
- **업무 데이터**: `bigint identity` (SERIAL/BIGSERIAL) 권장
- **외부 연계**: `uuid` 사용 가능
- **마스터 Seed**: `natural key` 우선

### 4.2 FK 정책 및 인덱스 가드레일
- **기본 정책**: `ON DELETE RESTRICT` (임의의 `CASCADE DELETE` 사용 절대 금지)
- **생성 방식**: 모든 테이블의 `CREATE TABLE`문이 완전히 끝난 후, 파일 최하단에 `ALTER TABLE ADD CONSTRAINT`문으로 일괄 생성한다. (테이블 생성 순서 꼬임 방지)

## 6. Soft Delete & Unique 인덱스 규칙
- **기본 원칙**: 모든 일반 업무 테이블(`cptb_*`)은 논리 삭제(Soft Delete)를 기본으로 삼는다.

| 컬럼명 | DB 타입 | Nullable | 기본값 | 제약 조건 |
| :--- | :--- | :---: | :--- | :--- |
| `del_yn` | `char(1)` | NOT NULL | `'N'` | `CHECK (del_yn IN ('Y', 'N'))` |
| `update_dt` | `timestamptz` | YES | NULL | — |
| `update_uid` | `varchar(64)` | YES | NULL | — |

- **[예외 대상 테이블]**: 매핑 및 시스템 공통 관계 테이블인 **`cmn_role_menu`**, **`cmn_role_pgm`**은 Soft Delete 대상에서 **제외**한다. 해당 테이블들은 데이터 삭제 요청 시 물리 삭제(Hard Delete)를 허용하며, 위 3개의 `del_*` 컬럼을 생성하지 않는다.
- **Unique 인덱스 주의사항**: Soft Delete 테이블에 Unique 제약/인덱스를 걸 때는, 삭제된 행(`del_yn = 'Y'`)과 활성 행이 동일 비즈니스 키를 동시에 갖지 않도록 설계한다.

### 6.1 SPEC `del_yn` (Soft Delete) — CPMS 고정

- **`del_yn`** 은 DB **`CHAR(1)`**, 값 **`'Y'` / `'N'`** 만 허용한다. **PostgreSQL `BOOLEAN` 컬럼이나 SPEC `logical_type: boolean` 으로 두지 않는다.**
- SPEC `# 4.1 Columns`에서는 `logical_type`에 **`yn_flag`** 를 사용한다 (본 문서 §3 표). Java·Mapper·Vue는 관례에 따라 **`String`** (`'Y'`, `'N'`)으로 맞춘다.
- **Data Engineer** DDL/`db_init_sql` 생성 시에도 **`del_yn CHAR(1)`** 패턴을 벗어나지 않는다.
